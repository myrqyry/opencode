## Locked decisions

### Workspace/tab architecture (implemented first pass)
- **Top titlebar tabs are projects, not chats.** `TitlebarProjectStrip` derives one project tab from the existing flat open chat/draft store, groups worktrees/sandboxes by canonical project identity where metadata is available, remembers the last-active chat per project, and closes a project's open chat group without deleting/archiving project sessions.
- **Middle-pane tabs are chats for the active project.** `SessionChatTabs` filters the existing chat/draft store by active project/worktrees, follows child-session routes back to their root chat, provides individual chat close actions, and its `+` opens another draft in that project. The same strip is present on the draft/new-session page.
- **Left sidebar Projects remains the full project library**, including projects with no open chats. Expanding a project shows only a compact recent-session slice (target: 5 initially) with `Load more` pagination so long-lived projects do not flood the sidebar. Selecting a historical chat opens it into that project's middle tab strip.
- **The former standalone `OPEN` section is now `CHATS`**, an always-expanded/non-collapsible active-project history. It shows 5 recent root chats initially, highlights the current root chat, and paginates by 5 through `Load more`; selecting history opens/selects that chat in the middle strip. Expanded project rows use the same 5 + `Load more` session list.
- **Right pane is workspace/project-scoped resources.** V2 uses workspace-scoped layout tabs for pinned `Files` and `Changes` plus opened file tabs. `Changes` exposes `Git changes` / `Last turn changes` (and branch mode when applicable); turn changes follow the active chat while open resource/file state survives chat switches in the same workspace. The old standalone `#file-tree-panel` is disabled in V2.
- **Changed-file diffs are collapsible per file**, using the existing review-open path state where practical, with expand/collapse-all affordances if the review list needs them.
- Reuse the existing flat chat/draft `TabsProvider` as backing state and derive project groups rather than migrating/replacing session persistence. Promote/use the existing workspace-scoped tab state for right-pane resources where possible.

Observed implementation choices; confirm intent before changing:
- Local UI serving precedence is `OPENCODE_WEB_UI_DIR` → embedded UI → upstream proxy, with a path-traversal guard and SPA `index.html` fallback.
- Restart is opt-in via `OPENCODE_ALLOW_RESTART=1`; the endpoint returns `{ restarting: true, pid }` or 403, disposing instances and exiting with code 75.
- Global skill scanning is skipped only when `OPENCODE_DISABLE_GLOBAL_SKILLS` is set; implicit global config dirs are also skipped in that mode.
